# 너랑나랑 MySQL 영속화 적용안

상태: 2026-10-29 사용자 승인 범위로 구현·로컬 검증 완료. 운영 승인이 아님.

승인 시 보완: DB는 `neorang_narang`과 `life_diary`, 계정은 `nn_app`과
`life_diary_app`으로 분리한다. 이번 업무 테이블은 너랑나랑에만 만든다.
실행·복구 절차는 [로컬 MySQL 안내](../local-mysql.md), 실행 증거와 한계는
[검증 기록](../verification/2026-10-29-mysql-persistence.md)을 참조한다.

## 확인한 현재 상태

- Docker Desktop Linux 엔진 연결 정상, 컨테이너 없음.
- Windows MariaDB 서비스 실행 중. 기존 서비스·3306·데이터는 변경하지 않는다.
- 완료 API는 프로세스 메모리 저장소이며 인증은 항상 401인 기존 경계를 유지한다.
- 이전 MySQL 구성안이나 승인된 영속화 스키마는 현재 저장소에서 확인되지 않았다.

## 적용할 범위

별도 MySQL 컨테이너를 만들고 호스트 `127.0.0.1:3307`만 컨테이너 3306에 연결한다.
포트 충돌 시 기존 서비스를 중지하지 않고 작업을 중단한다. 전용 named volume과
`neorang_narang` 및 `life_diary` 데이터베이스, 제품별 전용 앱 계정을 사용한다. MariaDB 연결·데이터 이전은 없다.
비밀번호는 Git에서 제외된 로컬 환경 파일로 관리하며 출력하거나 추적하지 않는다.

기존 `CompletionStore` 계약을 구현하는 MySQL 저장소를 추가한다. 승인 대상 테이블은
`nn_completion_records`이며 다음 자료만 보존한다.

| 열 | 의미 |
|---|---|
| owner_sub, record_id | UUID 문자열, 복합 기본키 |
| course_number, participation_mode | 기존 메타데이터 계약 값 |
| completed_at | 원래 완료 시각, UTC 마이크로초 정밀도 |
| revision | 현재 버전 |
| deleted_at | 서버 UTC 삭제 시각, nullable |
| updated_at | 서버 UTC 변경 시각 |
| delete_base | 동일 삭제 재시도 판별용 기준 버전, nullable |

소유자별 잠금용 테이블 `nn_completion_owners`에 owner_sub 기본키를 두고
트랜잭션에서 잠금을 잡아 최초 생성·수정·삭제의 읽기/비교/쓰기를 직렬화한다.
잠금 행 생성도 같은 트랜잭션에 포함한다. 교착·연결 실패는 원문 없는 고정 503으로
반환하고 자동으로 메모리 저장소로 전환하지 않는다. 클라이언트는 동일 명령을 재시도한다.
격리 수준은 READ COMMITTED이며, 잠금을 얻기 전 스키마 조회가 오래된 snapshot을
만들지 않도록 한다. 연결은 명령별 생성·정리하며 worker 사이에 공유하지 않는다.

기존 API 경로·응답·소유자 격리·409 충돌·삭제 tombstone·삭제 재시도 계약을 유지한다.
이름·은혜 원문·서명·실제 사용자 자료·인증 제공자·Flutter 동기화는 추가하지 않는다.
MySQL 드라이버 의존성을 추가하고 설치한다. 새 DB 초기화는 명시적 관리 명령으로만
실행하고 앱 시작 시 자동 DDL은 하지 않는다. 적용 버전도 별도 관리 테이블로 확인한다.

## 검증과 복구

합성 자료로 새 설치, 중복 초기화, 소유자 격리, 생성 재시도, 동시 수정 한 건 성공/한 건
409, 삭제 재시도, 연결 실패 503, 앱·DB 재시작 후 보존을 검증한다. 기존 전체 테스트와
pip check를 실행한다. 현재 메모리 자료는 자동 추출·이전하지 않는다.

신규 독립 DB에 대한 최초 적용이며 기존 MariaDB 스키마 업그레이드는 없다. 후속 DB
버전 변경은 별도 migration과 이전 버전 업그레이드 검증이 필요하다. 합성 자료로 덤프를
만들고 별도 검증 DB에 복원하여 값·버전을 비교한다. 백업은 저장소 밖의 접근 제한 위치에
보관한다. 실제 사용자 자료 백업·수집은 이번 범위에 포함하지 않는다.

롤백은 앱 저장소 설정을 메모리 모드로 되돌리고 새 MySQL 컨테이너만 정지하는 방식이다.
DB와 volume은 보존한다. 메모리 모드에서는 DB 자료를 조회할 수 없으며 DB 자료를
메모리로 자동 이동하지 않는다. `down -v`, DROP, 기존 서비스 중지·재설정은 수행하지 않는다.

## 사용자 승인한 결정

위의 독립 MySQL·3307·전용 volume/DB, 두 업무 테이블과 버전 관리, 드라이버 설치,
신규 DB 초기화 및 합성 자료를 이용한 실행·재시작·백업/복원 검증. 운영 배포·인증 경계
변경·기존 MariaDB 접근은 포함하지 않는다.
