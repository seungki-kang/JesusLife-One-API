# ChurchOS 소속 조회 첫 구현

상태 **AUTHOR_REVIEW_REQUIRED**.

`GET /api/v1/churches/{church_id}/membership`는 인증된 계정 자신의 활성
소속과 권한만 반환한다. 활성 소속에 부가 권한이 없으면 200과 빈 권한 목록,
소속 없음·철회는 403, 소속 DB 장애는 503이다. 미인증은 기존 인증 경계를 따른다.

PC 개발 앱 팩터리에 검증용 PostgreSQL 연결을 명시적으로 주입할 때만 등록한다.
Auth0 개발 토큰에는 `churchos:membership:read`가 필요하다. 기본 앱은
변경하지 않는다. 이 경로는 개인 기록이나 교회 전체 명단을 제공하지 않는다.

PostgreSQL의 `jl_churchos.memberships`가 소속 읽기 원본이다.
Migration 002는 001의 역할이 있는 격리 환경에서 관리자가 한 트랜잭션으로
실행하는 초안이다. 역할 관리 권한 필드는 조회 결과이며 쓰기 권한 부여
경로는 없다. 계정과 교회 UUID의 원본이 아직 같은 DB로 이관되지 않았으므로
외래 키와 관리자 소속 등록·철회 흐름은 후속 작업이다.

통합 검증은 임시 PostgreSQL에서 새 설치 및 역할 제한, 활성 소속과 철회,
DB 오류, 기본 앱의 경로 미등록을 확인한다. 실패 시 migration 트랜잭션을
롤백한다. 적용 후 되돌릴 때는 경로를 비활성화하고 소속 데이터를 보존한
상태에서 역 migration과 백업 복원을 별도로 검증한다.
